# T12: Determinism lint and the load-sensitive capture bound

You are working on the SWT Visual Oracle, a harness that renders each SWT widget through a native backend and a Skija backend and diffs the images, so renderer work can be verified by machine instead of by a person looking at screenshots.

Read first, they are the specification and this brief does not restate them:

- `docs/visual-oracle/SPI.md`, the frozen SPI, authoritative
- `docs/visual-oracle/PLAN.md`, especially "Key design decisions"
- `docs/visual-oracle/TRACKING.md`, sections "Work protocol" and "Quality bar"

Eleven tasks are merged. `tools/oracle/build.sh <backend>` prints a classpath, `tools/oracle/build-harness.sh` compiles the harness, `tools/oracle/oracle selftest` passes 33 checks over a 149-specimen catalog and must stay green.

## Scope

Two things, one of them a known defect that blocks CI.

**1. Fix the load-sensitive capture bound.** `CHECK 14 catalog-triple-render-deterministic` fails roughly one run in nine when the machine is busy, and passes consistently when it is idle. The capture runtime waits for a rendering to persist byte-identical across an observation window, bounded at 60 grabs and 5 seconds. Under CPU contention a GTK theme transition can outlast that bound, so a specimen is reported non-deterministic when really the machine was too slow.

This is a false negative, not a false pass, so it hides nothing. It does make unattended CI unreliable, and T21 cannot land until it is fixed.

Distinguish the two cases the current code conflates: **did not settle in time** and **settled differently**. A specimen that produced one stable value and then changed is a real determinism failure. A specimen that never produced a stable value under load is a timeout, and a timeout deserves a retry with a longer bound before it is called a failure. Scaling the bound with observed system load is another option. Measure, decide, and say why in the code.

Prove the fix: demonstrate the check surviving heavy load. Generate load deliberately, for example with several `yes > /dev/null` processes or a parallel build, and show the check passing where it previously failed. A fix you cannot demonstrate under load is not a fix.

**2. The determinism lint as a first-class facility.** Determinism is currently checked inside `SelfTest`. Promote it into something a catalog author can run directly on their own specimens, with a quarantine list for specimens known to be non-deterministic and deliberately excluded, each with a recorded reason. A dropped specimen with a reason is good; a silently missing one is not.

Several specimens were dropped by earlier tasks for animation reasons and later restored; `SWT.INDETERMINATE` progress bars are excluded permanently. Make that state visible rather than folklore in handoff records.

## Rules earlier tasks in this project learned the hard way

**Scratch goes in `/tmp/opencode/oracle-T12/` and nowhere else outside this worktree.** Other external paths are auto-rejected non-interactively and your run stops with no useful error.

**Never read PNG or other image files into your context.** Use ImageMagick from the shell (`compare -metric AE a.png b.png null:`, `identify`) and quote only the numbers. Reading images is the likeliest cause of the provider stream drops that cost an earlier task six sessions.

**Never use `git stash`.** The stash stack is repository-wide and several agents share this repository. To compare against the base commit, use `git worktree add --detach /tmp/opencode/oracle-T12-base <sha>`.

**Commit early, amend as you go.** The endpoint drops streams unpredictably; a driver resumes you automatically, but only committed work survives cleanly.

**Never weaken a check to make it pass.** Fix the cause. Never mark verified what you did not run.

**Do not push and do not open a pull request.**

## Running anything graphical

Always, without exception:

```bash
env -u WAYLAND_DISPLAY -u XDG_SESSION_TYPE GDK_BACKEND=x11 LIBGL_ALWAYS_SOFTWARE=1 \
  xvfb-run -a -s "-screen 0 1600x1200x24" <command>
```

With the Wayland variables set, `xvfb-run` silently renders on the real compositor and the run is not headless.
