# T11: Backend adapter for the SWT.SKIA canvas (PR 3231)


You are working on the SWT Visual Oracle, a harness that renders each SWT widget through a native backend and a Skija backend and diffs the images, so renderer work can be verified by machine instead of by a person looking at screenshots.

Read first, they are the specification and this brief does not restate them:

- `docs/visual-oracle/PLAN.md`, especially "Key design decisions"
- `docs/visual-oracle/TRACKING.md`, sections "Work protocol" and "Quality bar"

Fifteen tasks are merged. `tools/oracle/build.sh <backend>` prints a classpath, `tools/oracle/build-harness.sh` compiles the harness, `tools/oracle/oracle selftest` passes 53 checks over a 149-specimen catalog and must stay green.
## Scope

Make PR 3231's `SWT.SKIA` canvas a first-class `Backend`, the counterpart to the merged `SkijaProtoBackend` (T10). Read that adapter first and follow its shape: reflection against loaded classes, explicit activation evidence, coverage by measurement.

`tools/oracle/build.sh skia-canvas` builds it and `tools/oracle/verify-backend.sh skia-canvas` proves activation via the `org.eclipse.swt.external.canvas:logActivation` property.

The essential difference from the fork, and the thing this adapter must get right: **PR 3231 only migrates `Canvas`, plus `CLabel` through the style mask.** Almost the entire 149-specimen catalog is therefore genuinely unsupported by this backend, and that is correct rather than a defect. `Backend.supports` must reflect it honestly, and the coverage number this produces is a real measurement of how much of SWT that PR covers today.

Two known facts to encode rather than rediscover:

- `ExternalCanvasHandler.isActive` excludes `StyledText` and `Decorations`, and `Shell` extends `Decorations`.
- `SWT.SKIA` is `1 << 23`, the same bit as `SWT.FLAT`, which `Button` and `ToolBar` use. Any specimen carrying `SWT.FLAT` cannot meaningfully request `SWT.SKIA`. Report this rather than working around it; it is a finding about the PR's API design.

**A HiDPI defect worth confirming with numbers.** Run on a display scaled to 200 percent and the Skia canvas renders at roughly half size while the native canvas honours the zoom. Reproduce it through this backend at `zoomPercent` 200 and record the measured sizes. The environment control from T05 gives you per-zoom child processes; use them.

## Rules earlier tasks in this project learned the hard way

**Scratch goes in `/tmp/opencode/oracle-T11/` and nowhere else outside this worktree.** Other external paths are auto-rejected non-interactively and your run stops with no useful error.

**Never read PNG or other image files into your context.** Use ImageMagick from the shell (`compare -metric AE a.png b.png null:`, `identify`) and quote only the numbers. Reading images is the likeliest cause of the provider stream drops that cost an earlier task six sessions.

**Never use `git stash`.** The stash stack is repository-wide and several agents share this repository. To compare against the base commit, use `git worktree add --detach /tmp/opencode/oracle-T11-base <sha>`.

**Commit early, amend as you go.** The endpoint drops streams unpredictably; a driver resumes you automatically, but only committed work survives cleanly.

**Never weaken a check to make it pass.** Fix the cause. Never mark verified what you did not run.

**Do not push and do not open a pull request.**

## Running anything graphical

Always, without exception:

```bash
env -u WAYLAND_DISPLAY -u XDG_SESSION_TYPE GDK_BACKEND=x11 LIBGL_ALWAYS_SOFTWARE=1 \
  xvfb-run -a -s "-screen 0 1600x1200x24" <command>
```

With the Wayland variables set, `xvfb-run` silently renders on the real compositor and the run is not headless.
