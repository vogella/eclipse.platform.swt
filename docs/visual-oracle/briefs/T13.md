# T13: Specimen catalog, buttons and labels

You are working on the SWT Visual Oracle, a harness that renders each SWT widget through a native backend and a Skija backend and diffs the images, so renderer work can be verified by machine instead of by a person looking at screenshots.

Read first, they are the specification and this brief does not restate them:

- `docs/visual-oracle/SPI.md`, the frozen SPI, authoritative, especially `Specimen`, `SpecimenContext`, `SpecimenModule`, `SpecimenCatalog` and `Tag`
- `docs/visual-oracle/PLAN.md`, especially "Key design decisions" and the T13 row of the task table
- `docs/visual-oracle/TRACKING.md`, sections "Work protocol" and "Quality bar"

`tools/oracle/build-harness.sh` compiles the harness and `tools/oracle/oracle selftest` must stay green.

## Scope

The first real widget family in the specimen catalog: buttons and labels.

Cover `Button` in every style (`PUSH`, `CHECK`, `RADIO`, `TOGGLE`, `ARROW` with its four directions), plus `Label`, `CLabel` and `Link`. For each, cover the states and configurations that actually change rendering: enabled and disabled, with and without an image, text alignment, `SWT.BORDER`, `SWT.WRAP` where it applies, `CLabel` with an image and shadow styles, `Link` with and without markup.

Aim for coverage that would catch a real renderer defect, not for a specimen count. A `Button` that differs from native only when disabled is a defect this catalog must be able to find.

Contribute them as `SpecimenModule` implementations in `org.eclipse.swt.visualoracle.catalog`, one module per family, discovered automatically. **There is deliberately no central registration file**: other agents are adding other families in parallel, and a shared list would make every one of them conflict. Add files, never edit shared ones.

Ids are lowercase dot-separated and stable forever, because results reference them: `button.push.default`, `button.check.disabled`, `clabel.image.right`.

`org.eclipse.swt.visualoracle.impl.ButtonPushSpecimen` is the existing reference specimen. Move it into your module if that is cleaner, keeping its id `button.push.default` unchanged.

## Determinism is the hard requirement

A specimen whose rendering varies between two captures is worse than a missing specimen: it produces false differences that waste a person's attention.

The traps in this family specifically: focus rings, hover state, the caret in a focused control, and mnemonic underlines that appear only after Alt is pressed. Decide deliberately for each specimen whether focus is part of what you are testing, and if it is, set it explicitly rather than letting it happen. Tag focus-dependent specimens with `Tag.FOCUS_SENSITIVE`.

Do not use wall-clock time, random values or system locale in any specimen.

## Check your own work

```bash
tools/oracle/build-harness.sh && tools/oracle/oracle selftest
```

It must stay 8 of 8. Add a check that exercises the catalog:

- `SpecimenCatalog.discover()` finds your module and every specimen you contributed
- every specimen in the catalog has a unique, well-formed id
- **every specimen renders identically when captured three times in one process**, which is the determinism requirement and the check most likely to find a real problem in your own work
- every specimen produces a capture of its `preferredSize()`

Use the existing capture implementation as it stands; do not work around it if it is imperfect, and note anything you hit in your handoff instead.

## Rules earlier tasks in this project learned the hard way

**Scratch goes in `/tmp/opencode/oracle-t13/` and nowhere else outside this worktree.** Other external paths are auto-rejected non-interactively and your run stops with no useful error.

**Never read PNG or other image files into your context.** Use ImageMagick from the shell (`compare -metric AE a.png b.png null:`, `identify`) and quote only the numbers. Reading images is the likeliest cause of the provider stream drops that cost an earlier task six sessions.

**Commit early, amend as you go.** The endpoint drops streams unpredictably; a driver resumes you automatically, but only committed work survives cleanly. Commit after the first family builds, then amend.

**Never weaken a check to make it pass.** If a specimen is not deterministic, fix the specimen or drop it and say why. Never loosen the determinism check.

**Do not push and do not open a pull request.**

## Running anything graphical

Always, without exception:

```bash
env -u WAYLAND_DISPLAY -u XDG_SESSION_TYPE GDK_BACKEND=x11 LIBGL_ALWAYS_SOFTWARE=1 \
  xvfb-run -a -s "-screen 0 1600x1200x24" <command>
```

With the Wayland variables set, `xvfb-run` silently renders on the real compositor and the run is not headless.
