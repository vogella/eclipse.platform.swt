# T10: Backend adapter for prototype-skija

You are working on the SWT Visual Oracle, a harness that renders each SWT widget through a native backend and a Skija backend and diffs the images, so renderer work can be verified by machine instead of by a person looking at screenshots.

Read first, they are the specification and this brief does not restate them:

- `docs/visual-oracle/SPI.md`, the frozen SPI, authoritative
- `docs/visual-oracle/PLAN.md`, especially "Key design decisions"
- `docs/visual-oracle/TRACKING.md`, sections "Work protocol" and "Quality bar"

Eleven tasks are merged. `tools/oracle/build.sh <backend>` prints a classpath, `tools/oracle/build-harness.sh` compiles the harness, `tools/oracle/oracle selftest` passes 33 checks over a 149-specimen catalog and must stay green.

## Scope

Make the `skija-proto` backend a first-class `Backend` implementation so the harness can compare the fork's custom-drawn widgets against native.

`tools/oracle/build.sh skija-proto` already builds the fork and `tools/oracle/verify-backend.sh skija-proto` already proves it activates, reporting `PROBE-GC=org.eclipse.swt.graphics.SkijaGC`. What is missing is the adapter that lets the harness drive it like any other backend.

Two facts that shape the work:

- The fork draws widgets with Skija but keeps a native peer per widget, so the whole existing catalog applies to it directly, unlike PR 3231's canvas-only backend.
- The fork pins Skija 0.116.3 with jars committed in its tree, while PR 3231 expects 0.143.17 from Maven Central. Each backend has its own class output and classpath, and they must never mix.

`Backend.supports(Specimen)` is the important part. The fork does not render every widget through Skija, and a specimen it does not cover must report as unsupported rather than as a rendering defect. Determine coverage by evidence, not assumption: a widget whose GC is not a `SkijaGC` is not covered. Counting unsupported specimens is a useful migration progress metric, so make that number easy to obtain.

Expect gaps and report them rather than working around them. The fork's own log already shows `Not implemented yet: SkijaGC.getClipping` and `SkijaGC.setClipping`, so anything depending on clipping may fail; record what fails and why.

## Rules earlier tasks in this project learned the hard way

**Scratch goes in `/tmp/opencode/oracle-T10/` and nowhere else outside this worktree.** Other external paths are auto-rejected non-interactively and your run stops with no useful error.

**Never read PNG or other image files into your context.** Use ImageMagick from the shell (`compare -metric AE a.png b.png null:`, `identify`) and quote only the numbers. Reading images is the likeliest cause of the provider stream drops that cost an earlier task six sessions.

**Never use `git stash`.** The stash stack is repository-wide and several agents share this repository. To compare against the base commit, use `git worktree add --detach /tmp/opencode/oracle-T10-base <sha>`.

**Commit early, amend as you go.** The endpoint drops streams unpredictably; a driver resumes you automatically, but only committed work survives cleanly.

**Never weaken a check to make it pass.** Fix the cause. Never mark verified what you did not run.

**Do not push and do not open a pull request.**

## Running anything graphical

Always, without exception:

```bash
env -u WAYLAND_DISPLAY -u XDG_SESSION_TYPE GDK_BACKEND=x11 LIBGL_ALWAYS_SOFTWARE=1 \
  xvfb-run -a -s "-screen 0 1600x1200x24" <command>
```

With the Wayland variables set, `xvfb-run` silently renders on the real compositor and the run is not headless.
