# T07: Defect classification

## Scope

Map what the diff engine measures onto `DefectClass`, so a report can say what kind of defect a difference is rather than only how many pixels changed.

`ClusterDiffer` (T06) already produces verdicts, changed-pixel counts, maximum channel delta and connected clusters with bounds. Your job is the interpretation layer: given those clusters and the two images, decide the probable defect class and justify it.

The classes worth separating, because they lead to different fixes:

- **shifted content**: the same shape drawn at an offset, which typically means a baseline or origin error rather than a drawing error
- **missing element**: something present in the reference and absent in the candidate, such as a focus ring or an icon
- **extra element**: the reverse
- **wrong colour**: the same geometry with different fill, which points at colour conversion rather than geometry
- **wrong glyph or text metrics**: differences concentrated on text, which point at font selection or measurement
- **size mismatch**: already reported as DIFFERENT over the whole area, and should classify as such rather than as a thousand small defects

A classification that is confidently wrong is worse than one that abstains, because it sends a person to the wrong part of the code. Where the evidence does not support a class, leave it unset, and make that an explicit outcome rather than an accident.

Prefer measurements the diff already has over new heuristics. Cross-correlation for shift detection, cluster geometry for missing versus extra, and colour histograms within clusters for colour errors are cheap; a bespoke image-understanding scheme is not.

## Explicitly not in scope

Changing the diff engine's verdicts or tolerance (T06, merged), the report (T19), the CLI (T20).

## Check your own work

Build synthetic defect pairs programmatically from a real capture, one per class, and prove each is classified correctly. At minimum: a shifted copy, a removed rectangle, an added rectangle, a recoloured fill, a text-only difference, and a size mismatch.

Also prove abstention: a difference that matches no class cleanly must classify as unknown rather than being forced into the nearest one.

## Rules earlier tasks in this project learned the hard way

**Scratch goes in `/tmp/opencode/oracle-T07/` and nowhere else outside this worktree.** Other external paths are auto-rejected non-interactively and your run stops with no useful error.

**Never read PNG or other image files into your context.** Use ImageMagick from the shell (`compare -metric AE a.png b.png null:`, `identify`) and quote only the numbers. Reading images is the likeliest cause of the provider stream drops that cost an earlier task six sessions.

**Never use `git stash`.** The stash stack is repository-wide and several agents share this repository. To compare against the base commit, use `git worktree add --detach /tmp/opencode/oracle-T07-base <sha>`.

**Commit early, amend as you go.** The endpoint drops streams unpredictably; a driver resumes you automatically, but only committed work survives cleanly.

**Never weaken a check to make it pass.** Fix the cause. Never mark verified what you did not run.

**Do not push and do not open a pull request.**

## Running anything graphical

Always, without exception:

```bash
env -u WAYLAND_DISPLAY -u XDG_SESSION_TYPE GDK_BACKEND=x11 LIBGL_ALWAYS_SOFTWARE=1 \
  xvfb-run -a -s "-screen 0 1600x1200x24" <command>
```

With the Wayland variables set, `xvfb-run` silently renders on the real compositor and the run is not headless.
