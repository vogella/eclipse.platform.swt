# T04: Capture runtime

You are working on the SWT Visual Oracle, a harness that renders each SWT widget through a native backend and a Skija backend and diffs the images, so renderer work can be verified by machine instead of by a person looking at screenshots.

Read first, they are the specification and this brief does not restate them:

- `docs/visual-oracle/SPI.md`, the frozen SPI, authoritative
- `docs/visual-oracle/PLAN.md`, especially "Key design decisions" and the T04 row of the task table
- `docs/visual-oracle/adr/ADR-001-capture-strategy.md`, which decided how capture works and why
- `docs/visual-oracle/TRACKING.md`, sections "Work protocol" and "Quality bar"

Three tasks are merged and you build on them. `tools/oracle/build.sh <backend>` prints a classpath, `tools/oracle/build-harness.sh` compiles the harness, `tools/oracle/oracle selftest` must stay green.

## Scope

Replace the placeholder capture with a real capture runtime.

`org.eclipse.swt.visualoracle.impl.CopyAreaCapture` is a minimal reference implementation written only to make the skeleton run. Your job is the production version behind the same `Capture` interface: correct, deterministic, and usable by thousands of specimens in one run.

What the runtime owns, and what makes this more than a wrapper around `GC.copyArea`:

1. **Shell and control lifecycle.** Create the shell, host the specimen, size it to `preferredSize()`, lay out, capture, dispose. Specimens never do any of this. Reusing one shell across specimens is much faster than creating one per specimen; if you reuse, prove that specimen N's rendering cannot be influenced by specimen N-1.

2. **Settling.** A capture taken before the widget has finished painting is the single most likely source of flaky results in this project. Pump the event loop until the widget is genuinely stable rather than sleeping a fixed time. Say in the code why your settling condition is sufficient.

3. **Both strategies behind one interface.** `copyArea` primary, X11 grab fallback, chosen explicitly rather than guessed. ADR-001 has the measurements: 0.52 ms against 154 ms, and `Control.print` is rejected outright because it is blind to GL content.

4. **Fix the known defect in the fallback.** ADR-001 records that the X11 grab's crop origin is offset at zoom 200, capturing a shifted region: 24 marker pixels on the top and left edges and only 15 distinct colours instead of 148. This task owns that fix. The spike that found it is `tools/oracle-spike/`, and `run-spike.sh` reproduces it.

5. **Failure handling.** A capture failure must surface as data, not as a crashed run: one specimen that cannot be captured must never abort a catalog of thousands. The SPI already has `CaptureFailedException`, `UnsupportedSpecimenException` and `UnsupportedEnvironmentException`; use them as documented.

## Check your own work

```bash
tools/oracle/build-harness.sh && tools/oracle/oracle selftest
```

It must stay 8 of 8, and you extend `SelfTest` with checks for what you add. At minimum:

- the same specimen captured repeatedly in one process is byte-identical
- the same specimen captured in separate processes is byte-identical
- the X11 grab fallback and `copyArea` agree on the same specimen at zoom 100 **and** at zoom 200, which is what proves the crop fix
- a specimen whose creation throws is reported as a failure and does not abort the run

A check that passes because it asserts nothing is worse than no check at all.

## Rules earlier tasks in this project learned the hard way

**Scratch goes in `/tmp/opencode/oracle-t04/` and nowhere else outside this worktree.** Other external paths are auto-rejected non-interactively and your run stops with no useful error.

**Never read PNG or other image files into your context.** Use ImageMagick from the shell (`compare -metric AE a.png b.png null:`, `identify`) and quote only the numbers. Reading images is the likeliest cause of the provider stream drops that cost an earlier task six sessions.

**Commit early, amend as you go.** The endpoint drops streams unpredictably; a driver resumes you automatically, but only committed work survives cleanly. An earlier task made 49 tool calls before its first commit and lost all of it.

**Never weaken a check to make it pass.** Fix the cause. Never mark verified what you did not run.

**Do not push and do not open a pull request.**

## Running anything graphical

Always, without exception:

```bash
env -u WAYLAND_DISPLAY -u XDG_SESSION_TYPE GDK_BACKEND=x11 LIBGL_ALWAYS_SOFTWARE=1 \
  xvfb-run -a -s "-screen 0 1600x1200x24" <command>
```

With the Wayland variables set, `xvfb-run` silently renders on the real compositor and the run is not headless.
