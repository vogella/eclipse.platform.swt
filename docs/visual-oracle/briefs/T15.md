## Scope

The item widgets: `Table`, `Tree` and `List`. This is the largest family in the catalog and the one where renderer defects are most likely to hide, because these widgets draw many small elements: headers, gridlines, expanders, checkboxes, selection highlights and alternating rows.

Cover, at minimum:

`Table`: with and without headers, with and without gridlines, single and multi column, `SWT.CHECK`, a selected row, an unselected table, column alignment left/centre/right, a column with an image, and an empty table with headers.
`Tree`: collapsed and expanded, nested to two levels, `SWT.CHECK`, a selected node, with images, and an empty tree.
`List`: single and multi selection, with a selection and without, disabled, and more items than fit so the scrollbar appears.

Fill items with fixed, short, ASCII content. Never generate item text from a loop counter formatted with locale-dependent formatting, and never from time.

Aim for coverage that would catch a real renderer defect, not for a specimen count. A `Tree` whose expander arrow renders wrongly only when expanded is exactly the defect this family exists to catch.

Contribute them as `SpecimenModule` implementations in `org.eclipse.swt.visualoracle.catalog`, one module per family, discovered automatically. **Never add a central registration list**: other agents are adding other families in parallel, and a shared list would make every one of them conflict. Add files, do not edit shared ones.

Ids are lowercase dot-separated and stable forever: `table.headers.gridlines`, `tree.expanded.checked`, `list.multi.selected`.

## The hard part: selection, focus and scrollbars

A selected row in a focused widget draws differently from a selected row in an unfocused one, and GTK may animate the transition. The capture runtime returns a capture only once a rendering has persisted byte-identical across a live observation window, so anything still animating fails loudly rather than producing a random frame.

Set selection explicitly in `create` rather than letting focus decide it, and tag anything focus-dependent with `Tag.FOCUS_SENSITIVE`.

Scrollbars are the second trap: an overflowing `List` or `Table` may show an overlay scrollbar that fades, which will not settle. If that happens, measure it, and either size the specimen so the scrollbar is permanent or drop that specimen with the evidence.

## Rules earlier tasks in this project learned the hard way

**Scratch goes in `/tmp/opencode/oracle-t15/` and nowhere else outside this worktree.** Other external paths are auto-rejected non-interactively and your run stops with no useful error.

**Never read PNG or other image files into your context.** Use ImageMagick from the shell (`compare -metric AE a.png b.png null:`, `identify`) and quote only the numbers. Reading images is the likeliest cause of the provider stream drops that cost an earlier task six sessions.

**Commit early, amend as you go.** The endpoint drops streams unpredictably; a driver resumes you automatically, but only committed work survives cleanly. Commit as soon as the first family builds.

**Never weaken a check to make it pass.** Fix the specimen or drop it with evidence.

**Do not push and do not open a pull request.**

## Running anything graphical

Always, without exception:

```bash
env -u WAYLAND_DISPLAY -u XDG_SESSION_TYPE GDK_BACKEND=x11 LIBGL_ALWAYS_SOFTWARE=1 \
  xvfb-run -a -s "-screen 0 1600x1200x24" <command>
```

With the Wayland variables set, `xvfb-run` silently renders on the real compositor and the run is not headless.
