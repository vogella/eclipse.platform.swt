## Scope

The text entry family: `Text`, `Combo` and `Spinner`.

Cover what actually changes rendering. For `Text`: single line and multi line, `SWT.BORDER`, read-only, disabled, with and without content, `SWT.PASSWORD`, `SWT.SEARCH` with its icons, right-aligned and centred, and a message (placeholder) on an empty field. For `Combo`: read-only versus editable, with and without a selection, disabled, and a set width with an over-long item. For `Spinner`: default, with digits, disabled, and at its minimum and maximum.

Aim for coverage that would catch a real renderer defect, not for a specimen count.

Contribute them as `SpecimenModule` implementations in `org.eclipse.swt.visualoracle.catalog`, one module per family, discovered automatically. **Never add a central registration list**: other agents are adding other families in parallel, and a shared list would make every one of them conflict. Add files, do not edit shared ones.

Ids are lowercase dot-separated and stable forever: `text.single.border`, `combo.readonly.selected`, `spinner.digits.two`.

## The hard part: the caret

`Text`, `Combo` when editable, and `Spinner` all own a blinking caret, and a blinking caret is by definition not deterministic.

The existing capture runtime returns a capture only once a rendering has persisted byte-identical across a live observation window, which means a specimen with a visible blinking caret will not settle and will fail with a clear error rather than producing a random frame.

Decide deliberately how each specimen handles this and say why in your handoff. Options include not focusing the control at all, so no caret exists, or suppressing the blink. What you must not do is weaken the determinism check, add a special case for your specimens inside it, or accept a specimen that only passes sometimes.

Tag anything focus-dependent with `Tag.FOCUS_SENSITIVE`.

Also avoid: wall-clock time, random values, system locale, and text that renders differently depending on installed fonts beyond the pinned one.

## Rules earlier tasks in this project learned the hard way

**Scratch goes in `/tmp/opencode/oracle-t14/` and nowhere else outside this worktree.** Other external paths are auto-rejected non-interactively and your run stops with no useful error.

**Never read PNG or other image files into your context.** Use ImageMagick from the shell (`compare -metric AE a.png b.png null:`, `identify`) and quote only the numbers. Reading images is the likeliest cause of the provider stream drops that cost an earlier task six sessions.

**Commit early, amend as you go.** The endpoint drops streams unpredictably; a driver resumes you automatically, but only committed work survives cleanly. Commit as soon as the first family builds.

**Never weaken a check to make it pass.** Fix the specimen or drop it with evidence.

**Do not push and do not open a pull request.**

## Running anything graphical

Always, without exception:

```bash
env -u WAYLAND_DISPLAY -u XDG_SESSION_TYPE GDK_BACKEND=x11 LIBGL_ALWAYS_SOFTWARE=1 \
  xvfb-run -a -s "-screen 0 1600x1200x24" <command>
```

With the Wayland variables set, `xvfb-run` silently renders on the real compositor and the run is not headless.
