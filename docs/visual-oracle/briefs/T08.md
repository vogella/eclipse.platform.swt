# T08: Result model and JSON schema hardening

You are working on the SWT Visual Oracle, a harness that renders each SWT widget through a native backend and a Skija backend and diffs the images, so renderer work can be verified by machine instead of by a person looking at screenshots.

- `docs/visual-oracle/PLAN.md`, especially "Key design decisions"
- `docs/visual-oracle/TRACKING.md`, sections "Work protocol" and "Quality bar"

Eleven tasks are merged. `tools/oracle/build.sh <backend>` prints a classpath, `tools/oracle/build-harness.sh` compiles the harness, `tools/oracle/oracle selftest` passes 33 checks over a 149-specimen catalog and must stay green.

## Scope

The result JSON is not a convenience format, it is the comparison substrate: one process per backend and environment produces results, and comparison happens by merging those documents. Everything downstream, the report and the agent-facing CLI, parses it. Harden it into a contract.

1. **Version it explicitly.** A consumer must be able to tell which schema it is reading and fail clearly on an unknown version rather than misreading fields.

2. **Document every field** in `docs/visual-oracle/RESULT-SCHEMA.md`: meaning, type, whether it is optional, and what a consumer may rely on across versions. Fields that exist but are undocumented are fields nobody can safely use.

3. **Validate strictly and usefully.** The existing validator must reject unknown fields, wrong types and missing required fields, and say precisely what is wrong and where. A validator whose message is "invalid" costs more time than no validator.

4. **Round-trip guarantee.** Writing a result and reading it back must produce an equal model, including edge cases: empty runs, a specimen that failed to capture, a backend that does not support a specimen, and clusters with zero pixels.

5. **Stability under merge.** Merging results from several children must be deterministic: the same inputs in a different arrival order must produce byte-identical output, or the report will churn between runs for no reason.

## Rules earlier tasks in this project learned the hard way

**Scratch goes in `/tmp/opencode/oracle-T08/` and nowhere else outside this worktree.** Other external paths are auto-rejected non-interactively and your run stops with no useful error.

**Never read PNG or other image files into your context.** Use ImageMagick from the shell (`compare -metric AE a.png b.png null:`, `identify`) and quote only the numbers. Reading images is the likeliest cause of the provider stream drops that cost an earlier task six sessions.

**Never use `git stash`.** The stash stack is repository-wide and several agents share this repository. To compare against the base commit, use `git worktree add --detach /tmp/opencode/oracle-T08-base <sha>`.

**Commit early, amend as you go.** The endpoint drops streams unpredictably; a driver resumes you automatically, but only committed work survives cleanly.

**Never weaken a check to make it pass.** Fix the cause. Never mark verified what you did not run.

**Do not push and do not open a pull request.**

## Running anything graphical

Always, without exception:

```bash
env -u WAYLAND_DISPLAY -u XDG_SESSION_TYPE GDK_BACKEND=x11 LIBGL_ALWAYS_SOFTWARE=1 \
  xvfb-run -a -s "-screen 0 1600x1200x24" <command>
```

With the Wayland variables set, `xvfb-run` silently renders on the real compositor and the run is not headless.
