# T20: Agent-facing CLI

You are working on the SWT Visual Oracle, a harness that renders each SWT widget through a native backend and a Skija backend and diffs the images, so renderer work can be verified by machine instead of by a person looking at screenshots.

Read first, they are the specification and this brief does not restate them:

- `docs/visual-oracle/SPI.md`, the frozen SPI, authoritative
- `docs/visual-oracle/PLAN.md`, especially "Key design decisions"
- `docs/visual-oracle/TRACKING.md`, sections "Work protocol" and "Quality bar"

Fifteen tasks are merged. `tools/oracle/build.sh <backend>` prints a classpath, `tools/oracle/build-harness.sh` compiles the harness, `tools/oracle/oracle selftest` passes 53 checks over a 149-specimen catalog and must stay green.

## Why this task is the point of the project

Everything so far exists so that an agent can change a renderer, run one command, and get a verdict without a human looking at an image. `selftest` proves the machinery works; it does not let anyone use it. This task does.

## Scope

Implement the `run` and `triage` verbs sketched in `PLAN.md` under decision D5, attaching where T03 left the hooks.

```
oracle run --widget Button --state hover --dpi 150 --format json
oracle triage --top 20
```

1. **`run`** executes a comparison: for a selected set of specimens, capture through the reference backend and through a candidate backend, diff, classify, and report. Selection must be filterable by specimen id prefix, family, tag and environment. Running everything must also work and is the common case for CI.

   Remember the process model, decision D6: one process serves one backend and one environment, so `run` drives child processes through the merged `ChildProcessLauncher` and compares the merged JSON. Do not attempt in-process backend switching.

2. **`triage`** ranks what a person or agent should look at first. Ranking is a judgement call: a widget where every specimen differs is one defect, not forty, and should not crowd out forty distinct single-specimen defects. Group by probable defect class and by widget family, and say what your ranking optimises for.

3. **Exit codes and output are a contract.** Zero when every selected specimen is within tolerance, non-zero otherwise. JSON on stdout must be stable and documented, because agents parse it. Human-readable output goes to stderr or behind a flag, never mixed into the JSON stream.

4. **Documentation** in `docs/visual-oracle/CLI.md`: every verb, every flag, the exit codes, and one worked example of an agent using it to iterate on a renderer.

## Rules earlier tasks in this project learned the hard way

**Scratch goes in `/tmp/opencode/oracle-T20/` and nowhere else outside this worktree.** Other external paths are auto-rejected non-interactively and your run stops with no useful error.

**Never read PNG or other image files into your context.** Use ImageMagick from the shell (`compare -metric AE a.png b.png null:`, `identify`) and quote only the numbers. Reading images is the likeliest cause of the provider stream drops that cost an earlier task six sessions.

**Never use `git stash`.** The stash stack is repository-wide and several agents share this repository. To compare against the base commit, use `git worktree add --detach /tmp/opencode/oracle-T20-base <sha>`.

**Commit early, amend as you go.** The endpoint drops streams unpredictably; a driver resumes you automatically, but only committed work survives cleanly.

**Never weaken a check to make it pass.** Fix the cause. Never mark verified what you did not run.

**Do not push and do not open a pull request.**

## Running anything graphical

Always, without exception:

```bash
env -u WAYLAND_DISPLAY -u XDG_SESSION_TYPE GDK_BACKEND=x11 LIBGL_ALWAYS_SOFTWARE=1 \
  xvfb-run -a -s "-screen 0 1600x1200x24" <command>
```

With the Wayland variables set, `xvfb-run` silently renders on the real compositor and the run is not headless.
