## Scope

Replace `impl/ExactDiffer` with the real comparison engine behind the unchanged `Differ` interface.

`ExactDiffer` is a minimal reference implementation: it reports equality and a single bounding-box cluster. That is enough to prove the pipeline runs and useless for finding out *what* differs.

The engine you build decides whether a person ever has to look at an image, so what matters is not a single number but distinguishing the kinds of difference:

1. **Anti-aliasing tolerance that does not hide real defects.** Two renderers of the same glyph disagree by a channel or two on edge pixels. That must not read as a defect. A missing focus ring must, even though it is also thin and also on an edge. Getting that boundary right is most of this task; state the reasoning behind your thresholds, do not just pick numbers.

2. **Connected-component cluster detection.** A real diff is regions, not scattered pixels. Report clusters with bounds and pixel counts, ordered by significance, so a consumer can say "the difference is one 12x12 region in the top left" rather than "3.7 percent of pixels changed". A one-pixel-shifted baseline and a missing icon produce very different cluster shapes, and that is the signal the report and any future classification depend on.

3. **Size mismatch is DIFFERENT over the whole area, never an exception**, as `SPI.md` specifies. Widgets that lay out differently between backends are a defect the oracle must report, not a crash.

4. **Performance that suits the catalog.** The catalog already holds 42 specimens and grows to thousands across the DPI and theme matrix. A diff that takes a second per pair makes the full run unusable. Measure your throughput and state it.

`DefectClass` exists in the SPI and its detailed mapping is T07's task, not yours. Populate it only where your cluster analysis makes it obvious; leaving it unset is correct where it is not.

## Check your own work

```bash
tools/oracle/build-harness.sh && tools/oracle/oracle selftest
```

All existing checks must stay green, and you add checks for what you build. At minimum:

- identical images produce `EQUAL` with zero changed pixels and no clusters
- an image differing only in anti-aliasing on glyph edges is `WITHIN_TOLERANCE`, not `DIFFERENT`
- a synthetic defect that a human would call obvious, such as a removed rectangle or a shifted element, is `DIFFERENT` with a cluster that actually bounds the defect
- two separated defects produce two clusters, not one merged cluster spanning both
- a size mismatch is `DIFFERENT` over the whole area and throws nothing

Build your synthetic pairs programmatically from a real capture, so the test data is deterministic and no image files are needed.

## Rules earlier tasks in this project learned the hard way

**Scratch goes in `/tmp/opencode/oracle-t06/` and nowhere else outside this worktree.** Other external paths are auto-rejected non-interactively and your run stops with no useful error.

**Never read PNG or other image files into your context.** Use ImageMagick from the shell (`compare -metric AE a.png b.png null:`, `identify`) and quote only the numbers. Reading images is the likeliest cause of the provider stream drops that cost an earlier task six sessions.

**Commit early, amend as you go.** The endpoint drops streams unpredictably; a driver resumes you automatically, but only committed work survives cleanly.

**Never weaken a check to make it pass, and never widen a tolerance to make a comparison succeed.** A diff engine that reports agreement it has not established makes every later comparison in this project meaningless. If your tolerance cannot separate anti-aliasing from a thin real defect, say so with the measurement rather than choosing the number that makes the check pass.

**Do not push and do not open a pull request.**

## Running anything graphical

Always, without exception:

```bash
env -u WAYLAND_DISPLAY -u XDG_SESSION_TYPE GDK_BACKEND=x11 LIBGL_ALWAYS_SOFTWARE=1 \
  xvfb-run -a -s "-screen 0 1600x1200x24" <command>
```

With the Wayland variables set, `xvfb-run` silently renders on the real compositor and the run is not headless.
