# T09: Native backend adapter, hardened


You are working on the SWT Visual Oracle, a harness that renders each SWT widget through a native backend and a Skija backend and diffs the images, so renderer work can be verified by machine instead of by a person looking at screenshots.

Read first, they are the specification and this brief does not restate them:

- `docs/visual-oracle/SPI.md`, the frozen SPI, authoritative
- `docs/visual-oracle/PLAN.md`, especially "Key design decisions"
- `docs/visual-oracle/TRACKING.md`, sections "Work protocol" and "Quality bar"

Fifteen tasks are merged. `tools/oracle/build.sh <backend>` prints a classpath, `tools/oracle/build-harness.sh` compiles the harness, `tools/oracle/oracle selftest` passes 53 checks over a 149-specimen catalog and must stay green.
## Scope

`impl/NativeBackend` was written by T03 as a minimal reference so the skeleton could run. It is now the reference oracle every comparison is measured against, and it has never been hardened. Everything the harness concludes rests on it being right.

1. **Support and refusal.** `supports` should reflect what the native backend can genuinely render, and refusal must be data rather than an exception, consistent with `SkijaProtoBackend` (T10, merged). Read that adapter and align.

2. **Activation evidence.** The other two backends prove they are active rather than assuming it. Native should too: a comparison silently running native against native would report perfect agreement and be worthless. Prove the GC in use is the native one.

3. **Environment fidelity.** The native backend must honour the process `RenderEnv` and refuse a mismatch, exactly as `Capture` does. A backend that quietly renders at the wrong zoom mislabels every result downstream.

4. **Cross-check the oracle against itself.** Native versus native over the whole catalog must be EQUAL for every specimen. Anything that is not equal is either a non-deterministic specimen or a defect in the harness, and either way it must be found now rather than blamed on a Skija renderer later. Run it and report the numbers.

That last item is the most valuable thing in this task. It is the closest the project can get to validating its own oracle.

## Rules earlier tasks in this project learned the hard way

**Scratch goes in `/tmp/opencode/oracle-T09/` and nowhere else outside this worktree.** Other external paths are auto-rejected non-interactively and your run stops with no useful error.

**Never read PNG or other image files into your context.** Use ImageMagick from the shell (`compare -metric AE a.png b.png null:`, `identify`) and quote only the numbers. Reading images is the likeliest cause of the provider stream drops that cost an earlier task six sessions.

**Never use `git stash`.** The stash stack is repository-wide and several agents share this repository. To compare against the base commit, use `git worktree add --detach /tmp/opencode/oracle-T09-base <sha>`.

**Commit early, amend as you go.** The endpoint drops streams unpredictably; a driver resumes you automatically, but only committed work survives cleanly.

**Never weaken a check to make it pass.** Fix the cause. Never mark verified what you did not run.

**Do not push and do not open a pull request.**

## Running anything graphical

Always, without exception:

```bash
env -u WAYLAND_DISPLAY -u XDG_SESSION_TYPE GDK_BACKEND=x11 LIBGL_ALWAYS_SOFTWARE=1 \
  xvfb-run -a -s "-screen 0 1600x1200x24" <command>
```

With the Wayland variables set, `xvfb-run` silently renders on the real compositor and the run is not headless.
